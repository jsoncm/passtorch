## 1. 核心判断：为什么是「独立开源」

**一句话**：「跨厂商中立」这个最强护城河，一个挂商业品牌（360AgentDrive / eyun 云）的产品**无法可信地宣称**——用户凭什么信一个卖云备份的厂商会中立地帮所有 Agent 记忆？只有一个**本地优先、无云、MIT 开源、不绑任何厂商**的独立项目，才能让「中立」从话术变成用户可自行验证的事实。

因此正确结构是 **open-core（开放内核）**：

```
开源核心（本项目, MIT）          商业层（留在 AgentDrive）
─────────────────────           ─────────────────────
记忆 MCP server                  团队云同步（Team State Sync）
本地 daemon（共享大脑）           审计合规 / 精准定责
JSONL 记忆库                     双轨回滚引擎 / 灾备
只读观测页                       桌面托盘 Helper / 企业权限
单机跨厂商 remember/recall
        │
        └──── 引流 · 占 MCP 生态位 · 建社区信任 ──▶ 漏斗上游
```

**切分判据（唯一红线）**：凡「让数据离开本机」或「多人 / 合规」的 → 商业层；凡「单机本地」的 → 开源核心。这条线同时守住开源核心「本地优先中立」的纯粹性。

### 1.1 四个结构性理由

| 理由 | 说明 |
| --- | --- |
| **中立性只能由无品牌载体承载** | 商业产品宣称「中立帮所有 Agent 记忆」没人信；开源 + 本地 + 无云才可验证。这是护城河成立的**前提**。 |
| **MCP 有现成分发渠道** | `npx` 一行接入 + MCP registry / awesome-mcp / Claude & Cursor MCP 目录 = 开源基础设施的天然冷启动通道；商业 Electron 包吃不到。 |
| **开发者只信开源基础设施** | 「把我所有项目的试错记忆交给一个后台常驻进程」——这种信任只给可审计源码、数据留本机的开源项目。 |
| **与商业线互相成就** | 开源核心免费引流建口碑，团队 / 企业能力收费；两条线是漏斗上下游，不打架。 |

## 2. 竞品差异化（v1 定位必须先钉死）

赛道**已有玩家**，发布前必须想清「凭什么是你」：

| 竞品 | 它是什么 | 与本项目的本质差异 |
| --- | --- | --- |
| **mem0 / OpenMemory** | 通用 LLM 记忆层，向量检索，偏「记住事实 / 偏好」 | 它记 **fact**（你是谁、你偏好什么）；我们记 **event**（上一任 Agent 干了什么、为什么放弃）。层不同。 |
| **basic-memory / mcp-memory-service** | 本地 MCP 记忆（Markdown / 向量） | 它们是「给 Agent 的自由笔记本」；我们强制 **who/when/intent/evidence 四字段** = 带证据链和跨厂商归因，不是自由文本。 |
| **Letta (MemGPT)** | Agent 自带的长期记忆运行时 | 绑定它自己的 Agent 框架；我们是**框架外、跨厂商**的旁挂层。 |
| **Claude / Codex 官方记忆** | 各厂商自家 Agent 的记忆 | 天然锁在自己生态，**结构上不可能帮竞品记忆**——这正是我们不被吞的原因。 |

**v1 一句话定位（建议）**：

> **不是「让 Agent 懂得多」的知识库，是「换 Agent 也不失忆、不重复踩坑」的跨厂商事件 / 证据层。**

三个可演示差异支点：① 跨厂商（Claude 记的 Codex 能想起）② intent/evidence 而非纯 fact ③ 本地优先 + **只读观测页**（记忆过程肉眼可见，别家几乎都没有）。

## 3. v1 需求范围（MUST / SHOULD / DEFER）

发布标准的关键是**克制**——v1 只证一件事：换 Agent 不失忆，且装起来毫无摩擦。

### 🟢 MUST（v1 必须有；括号内标原型现状）

1. 记忆 MCP server：`remember` / `recall` 两个 tool（原型已有）
2. 本地共享 daemon + JSONL 存储，数据只落本机、只监听 `127.0.0.1`（原型已有）
3. 多 Agent 身份区分（`who` 字段）（原型已有）
4. 只读观测页（记忆库 + 调用流 + 连接状态）（原型已有，差异化卖点）
5. 四字段 schema `who/when/intent/evidence`（原型已有，核心资产）
6. **零摩擦安装**：`npx passtorch` 一行接入，无需手动起 daemon、无需读 `.port`（原型最大缺口，见 plan §2）
7. **项目自动识别**：`project` 由 git root / cwd 自动推导（原型缺，必补，见 plan §3）
8. **跨平台纯 Node 运行**：macOS / Linux / Windows（不能只依赖 bun，见 plan §1）
9. ≥3 个 Agent 接入文档：Claude Code / Codex / Cursor（原型只有 2 个）

### 🟡 SHOULD（v1 有更好，可放 v1.1）

- `list` 只读浏览工具（比 recall 更直接）
- Agent 侧 `forget` / `update`（**不违背观测页红线**：红线是「页面不给人写」，Agent 经 MCP 修正记忆合理）
- 配置文件（数据目录、端口、项目别名）
- 30 秒 demo GIF（跨厂商 recall 亮起观测页）——开源冷启动近乎刚需

### 🔴 DEFER（v1 明确不做，守住「第一个版本」边界）

- ❌ 向量 / 语义检索（v1 关键词够用；但 store 层留可替换接口）
- ❌ 记忆压缩 / TTL / scope 生命周期治理（字段预留，不实现）
- ❌ **云同步 / 团队共享**（上云即毁「本地优先中立」卖点，属**商业线**，绝不进开源核心）
- ❌ 审计 / 多人权限 / 合规（企业线）
- ❌ 双轨回滚 / git 集成 / 急救按钮 / 菜单栏托盘（属商业 AgentDrive 桌面端）
- ❌ Electron 桌面 App（开源核心 = CLI + MCP server + 本地网页，不做客户端）

## 5. 剥离路径（低成本、IP 干净）

1. 用你自己编写的原型代码，在 workspace 平级 `oss/passtorch/` 新建独立仓库（原型是**你的原创，不夹带任何上游 AionUi 代码**，IP 干净；`oss/` 与商业仓库平级，物理隔离）。
2. 按 plan §2 补齐「daemon 自启动 / 项目识别 / 纯 Node 产物 / store 抽象」四缺口 + 结构重排。
3. 以中立名 **`passtorch`** 落定命名与身份（去 AgentDrive / 360 品牌——中立性要求不挂商业品牌，已定案）。
4. 补齐 §4 社区 / 工程物料 → 发 npm（包名 `passtorch`）+ GitHub。
5. AgentDrive 主项目里，把「记忆能力」的实现从「进主项目自研」改为「**引用 `passtorch` 开源包**」（open-core 的商业层依赖开源核心）。

## 6. 风险登记

| 风险 | 缓解 / 立场 |
| --- | --- |
| mem0 / OpenMemory 已占位 | 用 intent/evidence + 跨厂商 + 观测页三点差异化，不做通用 fact 记忆 |
| 大厂出跨工具记忆标准（类 `mcp://memory`） | 3–5 年内厂商锁定动机强，标准化不太可能；这是建壁垒的时间窗 |
| 开源后商业价值被稀释 | open-core 严守 §1 切分红线，核心引流、云 / 团队 / 审计收费 |
| 剥离误带上游 IP | 只迁自己写的原型代码，发布前做 license 审计 |
| daemon 自启动做不稳 → 零摩擦卖点塌 | plan §2/P3 生命周期状态机是重点攻坚，先钉死（生死点） |
